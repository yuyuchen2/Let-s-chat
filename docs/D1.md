# Cloudflare D1 初始化与维护

`schema.sql` 是 LetsChat 唯一的全量建表文件。Worker 不会在请求路径中建表或修改表结构：这避免了每一个请求产生 DDL 开销，也避免了部署后将数据库错误悄悄吞掉。

## 1. 创建并绑定数据库

1. 登录 Cloudflare，并在仓库根目录安装依赖：`npm install --save-dev wrangler`，或使用 `npx wrangler`。
2. 认证：`npx wrangler login`。
3. 创建生产数据库：`npx wrangler d1 create chat_db`。
4. 将命令输出的 `database_id` 写入根目录 `wrangler.toml` 的 `[[d1_databases]]` 区块；绑定名称必须保持为 `DB`，因为 Worker 通过 `env.DB` 访问它。
5. 建议先创建本地数据库并验证 SQL：`npx wrangler d1 execute chat_db --local --file=schema.sql`。
6. 初始化远程生产数据库：`npx wrangler d1 execute chat_db --remote --file=schema.sql`。
7. 检查表和索引：

   ```bash
   npx wrangler d1 execute chat_db --remote --command "SELECT name, type FROM sqlite_master WHERE type IN ('table', 'index') ORDER BY type, name;"
   npx wrangler d1 execute chat_db --remote --command "PRAGMA table_info(users);"
   ```

8. 部署 Worker：`npx wrangler deploy`。

> 使用 connected Workers Builds 时不要在 CI 中硬编码 `account_id`；Cloudflare 会提供账户上下文。部署到不同账户时，必须替换为该账户中新建 D1 数据库的 ID。

## 2. 已有数据库升级

先备份并检查当前结构，**不要**直接把全量文件当作历史迁移文件执行，因为 `CREATE TABLE IF NOT EXISTS` 不会改变已存在表的列、约束或排序规则：

```bash
npx wrangler d1 export chat_db --remote --output=chat_db-backup.sql
npx wrangler d1 execute chat_db --remote --command "PRAGMA table_info(users);"
npx wrangler d1 execute chat_db --remote --command "PRAGMA index_list(messages);"
```

本仓库此前的 schema 已包含 Worker 所需的四张表及字段，因此可安全补上新查询所用索引：

```bash
npx wrangler d1 execute chat_db --remote --command "CREATE INDEX IF NOT EXISTS idx_messages_created_at_id ON messages (created_at DESC, id DESC);"
npx wrangler d1 execute chat_db --remote --command "CREATE INDEX IF NOT EXISTS idx_online_users_last_seen ON online_users (last_seen);"
```

若旧 `users` 表缺少 `failed_login_attempts` 或 `locked_until`，在部署当前 Worker 前分别执行一次：

```bash
npx wrangler d1 execute chat_db --remote --command "ALTER TABLE users ADD COLUMN failed_login_attempts INTEGER NOT NULL DEFAULT 0;"
npx wrangler d1 execute chat_db --remote --command "ALTER TABLE users ADD COLUMN locked_until INTEGER;"
```

SQLite/D1 不支持以可移植、幂等的方式为 `ALTER TABLE ... ADD COLUMN` 添加 `IF NOT EXISTS`。运行前务必通过 `PRAGMA table_info(users)` 确认列不存在；重复执行会失败但不会损坏数据。

## 3. 数据模型与例行清理

| 表 | 用途 | 关键索引 |
| --- | --- | --- |
| `users` | 账户、PBKDF2 密码哈希和锁定计数 | `username` 的唯一索引 |
| `sessions` | 7 天会话 token | `expires_at` |
| `messages` | 聊天记录 | `(created_at DESC, id DESC)` |
| `online_users` | 60 秒在线心跳 | `last_seen` |

在线用户会在读取列表时清理。过期会话不会自动删除，建议使用 Cloudflare Cron Trigger 每日调用清理逻辑，或定期运行：

```bash
npx wrangler d1 execute chat_db --remote --command "DELETE FROM online_users WHERE last_seen < unixepoch('now') * 1000 - 60000; DELETE FROM sessions WHERE expires_at <= unixepoch('now') * 1000;"
```

在生产环境变更 schema 前，先导出备份，在本地 D1 运行 SQL，并保留每一次实际执行的迁移 SQL 与日期。新功能应新增编号迁移文件，而不是编辑已应用的迁移。
